# Phase 1 Data Model: Doit Goal Tracker — Initial Page Setup

## Entity: Goal

Represents a single objective the user is tracking (spec Key Entities).

| Field | Type | Required | Notes |
|---|---|---|---|
| `id` | `string` | yes | Stable unique identifier, generated client-side (`crypto.randomUUID()`) when a goal is created. |
| `title` | `string` | yes | Non-empty after trimming whitespace (FR-006). No maximum length enforced; long titles wrap/truncate visually (Edge Cases). |
| `endDate` | `string` (ISO `YYYY-MM-DD`) | yes | The user-chosen deadline date (FR-005/006). Stored as a date-only string — no time-of-day component. |
| `status` | `"active" \| "completed"` | yes | Drives column placement (FR-001, FR-007). Defaults to `"active"` on creation. |
| `createdAt` | `string` (ISO datetime) | yes | Set once at creation; used as a stable tiebreaker when two active goals share an `endDate`. |
| `completedAt` | `string` (ISO datetime) \| `null` | yes | `null` while `status === "active"`; set to the completion timestamp when the checkbox is checked (FR-007). Drives completed-column ordering (FR-013). |

### Validation rules

- `title`: reject empty or whitespace-only values (FR-006).
- `endDate`: reject empty values and values that do not parse as a valid calendar date
  (FR-006). Past dates ARE allowed (Edge Cases: overdue goals stay active and
  highlighted, they are not rejected at creation).
- `id`: must be unique within the stored array; generated by the app, never user input.

### State transitions

```text
[created] --> active
active --> completed      (checkbox checked; sets completedAt = now)   [FR-007]
active --> (deleted)       (explicit delete + confirm)                 [FR-008/009]
completed --> (deleted)    (explicit delete + confirm)                 [FR-008/009]
```

- There is no `completed --> active` transition and no in-place edit of `title` or
  `endDate` (FR-014) — this is a one-way, append/complete/delete-only lifecycle for v1.

### Derived values (not stored)

- **Days left** (active goals only): `differenceInCalendarDays(parseISO(endDate), today)`.
  - `> 3`: shown as "N days left", not highlighted.
  - `0..3` (inclusive) or negative (overdue): shown as "due soon"/"overdue" and
    visually highlighted (FR-003, SC-002).
- **Sort key**:
  - Active column: ascending by `endDate`, then ascending by `createdAt` as a tiebreaker
    (FR-013).
  - Completed column: descending by `completedAt` (FR-013).
